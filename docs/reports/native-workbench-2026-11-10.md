# Native RMF workbench validation

Created by Jason Stys. Candidate version 1.1.0; local observations on 10–11 November 2026. [Practical usage and boundaries](../native-workbench.md).

## What changed and why

The original six-predicate evidence assessment, original NIST OSCAL schema validation, owner calendar and ledger are now available through actual graphical input/parameter controls. Users can select supported workspaces/reports/closed ledgers, retain findings, search literal evidence, inspect full records, export exact bundles and reopen durable history. Prepared fictional cases populate the ordinary controls in this full application. A changed input clears permission acknowledgement. Unknown evidence and NOT_GRANTED authorization remain visible rather than becoming a score or approval.

The Python report comparison retains source assessment identities and explicit scope/risk transitions. The separately compiled TypeScript reviewer remains independent; the actual interoperability demo now requires exact shared comparison fields to agree, beyond its original three-control/three-risk oracle. The native package does not require Node.

Selected ledger imports are copied into bounded staging and never modified. Active WAL/journal companions are refused. Application ID alone is insufficient: imported query-heavy views/virtual tables are rejected, SQLite cells are capped and each connection has a twenty-million-instruction work budget. Real hostile-view, oversized-cell and excessive-work tests preserve the original ordinary-ledger behavior. Blank expected tip is explicitly UNANCHORED_LOCAL_CHAIN; a supplied independently retained matching tip is only a comparison against that trust anchor.

## Runtime, notices and retained validation

The full Windows SDK and actual bundled runtime identity are checked; notices are collected from the real runtime/installed distributions, including Tcl/Tk 9 zipfs, Python and PyInstaller's applicable bootloader exception. `jsonschema[format-nongpl]` is the official supported extra replacing only the old GPL3+ rfc3987 leaf with exact hash-pinned MIT URI/Unicode-IRI parsers and their grammar. Both required format registration and genuine valid/invalid URI/Unicode IRI cases are tested; no silent format downgrade, advisory ignore or schema rewrite is used. See the [official jsonschema format guidance](https://python-jsonschema.readthedocs.io/en/stable/validate/#format) and [upstream parser package](https://pypi.org/project/rfc3987-syntax/).

The original four OS/Python quality lanes, official Python/Ajv interoperability and security gates remain. A new Windows lane uses exact Python 3.14.10, audits the full native lock, builds the complete EXE and runs the actual two-process consumer. No package/profile artifact or Actions cache is uploaded. Local observations above are candidate measurements with source_dirty=true, not hosted PR results. Fresh hosted results and clean-source native identity must be checked separately before release.

## Limits

Windows portable only; no macOS/Linux binary, installer, code signature or independent compliance/security audit claim. Plaintext owner-local SQLite is not multiuser authentication, encryption or forensic erasure. The 20-analysis/128 MiB payload limits reject over-cap saves without silently evicting evidence. Original Office publications remain historical measurements of their recorded sources. No collector, risk acceptance, government authorization, external request, host change or Docker action occurred.
